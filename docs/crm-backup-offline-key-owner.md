# Рабочий ключ age: действия владельца на доверенном Windows-компьютере

Рабочий закрытый ключ ещё не создан. AI не создаёт его в Railway, CI, чате или своём рабочем окружении. Эта процедура выполняется владельцем локально; резервирование клиентов и cron при этом не включаются.

## Подготовка до отключения интернета

1. Использовать доверенный Windows-компьютер с уже включённым BitLocker на диске, где расположен LOCALAPPDATA. Процедура не включает BitLocker и не меняет настройки Windows. Если проверка защиты недоступна или не проходит — остановиться.
2. Подготовить **два физических USB-накопителя**, не два раздела одного диска. Проверка скрипта требует разных Disk Number и BusType USB. Хранить накопители отдельно, например в двух разных закрытых местах. На них будут только зашифрованная identity, публичный recipient и контрольная сумма шифрованного файла.
3. Установить age по [официальной инструкции](https://github.com/FiloSottile/age#installation): `winget install --id FiloSottile.age -e`. Проверить `age --version` и наличие `age-keygen`. Сохранить [offline-key-setup.ps1](../backup/offline-key-setup.ps1) из проверенного коммита проекта. Скрипт не скачивает программы или ключи.
4. Подготовить сильную отдельную парольную фразу для шифрования закрытой identity. Вводить её только в интерактивный запрос age. Хранить в защищённом менеджере паролей или запечатанной независимой копии, отдельно от USB. Не отправлять в чат, не добавлять в команды или историю терминала. Потеря этой фразы делает обе зашифрованные копии ключа недоступными.
5. Отключить Wi-Fi и сетевой кабель. Скрипт проверяет отсутствие маршрута по умолчанию; он не отключает сеть сам. Использовать новую консоль без записи экрана и вывода закрытого ключа. Не размещать рабочие файлы в OneDrive/Dropbox или других синхронизируемых каталогах.

## Выполнение

В Windows PowerShell на доверенном компьютере, где доступна проверка BitLocker, перейти в папку со скриптом. Проверить настоящие буквы USB-дисков. Пример для **E:** и **F:**:

```powershell
powershell.exe -NoProfile -File .\offline-key-setup.ps1 -DriveA E -DriveB F -OwnerOfflineKeySetup
```

Если политика выполнения или защитное ПО блокирует операцию, **не использовать Bypass, не отключать защиту и не менять политику**. Остановиться и сообщить только код ошибки.

Скрипт создаёт новый уникальный приватный каталог на зашифрованном локальном диске, ограничивает ACL текущим пользователем, генерирует identity и зашифровывает её через интерактивный `age -p`. Затем делает две копии на независимых USB и сверяет SHA-256. После удаления первоначальной plaintext identity независимо восстанавливает ключ с каждого USB, сверяет публичный recipient и расшифровывает искусственный архив. В конце удаляет созданные временные локальные файлы. Это обычное удаление, не обещание физического стирания SSD; защита локального диска шифрованием обязательна. USB-копии никогда автоматически не удаляются.

При успешной проверке выводятся только:

```
OFFLINE_PRODUCTION_KEY_CUSTODY_OK independent_usb_disks=2 copies=ENCRYPTED original_removed=YES both_recoveries=PASS artificial_decrypt=PASS
PUBLIC_RECIPIENT=age1...
KEY_ID=...
```

Если проверка не прошла, не включать backup. Сохранить уже созданные зашифрованные USB-копии и сообщить только код ошибки; не присылать их в чат.

## Что можно сообщить AI

Только публичный `PUBLIC_RECIPIENT`, `KEY_ID` и строку успешной проверки. **Не присылать закрытый ключ, зашифрованные копии identity или парольную фразу.** После успешной проверки безопасно извлечь оба USB и хранить отдельно. В Railway позднее попадёт только публичный AGE_RECIPIENT, после проверки владельцем.

Рабочий ключ для аварийного восстановления расшифровывается только на доверенном компьютере в приватный временный каталог; его не загружают в Railway или Яндекс Диск. Искусственная контейнерная репетиция не заменяет проверку этих двух настоящих офлайн-копий.

Скрипт должен пройти синтаксическую проверку CI. Полный запуск с реальными USB/BitLocker и создание рабочего ключа AI не выполняет и не считает проверенными до локального результата владельца.
